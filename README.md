# Digital Work Systems Guidelines Prototype

Working prototype supporting interpretation and application of the *Work Health
and Safety Amendment (Digital Work Systems) Act 2026* (NSW). v1 is scoped to
the warehouse pick-rate use case, with reusable scaffolding for subsequent
cases.

**Status:** v1 prototype. Draft for internal discussion — not legal advice.

## What this is

A structured assistant for four roles — WHS entry permit holders, PCBU
representatives, HSRs/workers, and SafeWork inspectors — that walks a user
through the decision steps set out in the Act and produces a proportionate,
auditable output document (e.g. a s 118(1)(a1) notice).

See [`docs/spec-v1.md`](docs/spec-v1.md) for the full spec.

## Architecture

- **Deterministic core:** taxonomies, decision-tree rules, artefact registry,
  other-law flags, and templated output. All authored in YAML so a lawyer or
  policy officer can read and review them.
- **Assistive LLM layer (optional):** scoped to natural-language input parsing
  and plain-language explanation. Kept out of any decision the Act would put in
  front of a lawyer. Disabled by default in v1; see `src/llm_assist.py`.
- **Thin frontend:** Streamlit app (`app.py`) wiring the above.

```
content/
  taxonomies/        reusable taxonomies (§3)
  rules/             decision-tree rules — outer scaffolding + per-case branches
  artefacts/         artefact registry entries
  other_law/         other-law flags (§6)
  templates/         output templates
  scenarios/         case-specific scenario narratives
src/                 engine code (rule execution, registry lookup, audit log)
docs/                spec, governance, disclaimers
tests/               branch-coverage and schema tests
```

## Running the prototype

```bash
pip install -r requirements.txt
streamlit run app.py
```

## Running tests

```bash
pytest
```

Tests include a branch-completeness check (§11 success criterion) that asserts
every decision-tree branch terminates in an output step.

## Adding a new case

Per §12 of the spec, most of the build is reusable. To add a case:

1. Add a scenario narrative to `content/scenarios/<case>.yaml`.
2. Add inner-layer decision-tree branches to `content/rules/<case>.yaml`.
3. Add artefact entries to `content/artefacts/<case>.yaml`.
4. Tune other-law flags in `content/other_law/flags.yaml` if needed.
5. Add tests in `tests/`.

The taxonomies, outer decision-tree, registry schema, other-law module,
templates, governance framework, and success-criteria pattern do not change.

## Governance and disclaimers

See [`docs/governance.md`](docs/governance.md) and
[`docs/disclaimers.md`](docs/disclaimers.md). Every output generated by the
tool carries a guidance-not-legal-advice disclaimer and a reference to the Act
as the authoritative source.
